# Block execution verification

The accelerator executes mapped source procedures, not recognized search names.
`program_bytecode.cpp` lowers blocks; `program_vm.h` and `program_vm_ops.h` provide
the shared machine; `program_host.cpp` and `program_cuda_kernel.cu` implement its
physics operations. Unsupported programs retain the source interpreter and the
requested physics backend. Source APIs and editable graphs remain authoritative.

Current policy: CUDA source control uses the resident physics cursor by default.
`FOREVERTAS_CUDA_SOURCE_CURSOR=0` opts out; `1` explicitly enables it. Source
instructions and events still run at every consumed tick. Earlier opt-in
statements below describe historical revisions, not the current default.

## Resource and semantic checks

- The persistent CPU pool is bounded at 256 workers. Nested maps do not create
  additional pools, and CUDA interpreted branches have a one-session limit.
- Lane seeds are assigned before scheduling. GPU allocation retries replay only
  the uncommitted wave with the same arguments and seeds.
- GPU working arenas and compact output each start at 128 KiB per lane.
  Initial-value imports grow from 2 MiB to at most 64 MiB. Working arenas grow
  to fit those imports; their retry limit is at least 2 MiB and provides twice
  the rounded import capacity, capped at 64 MiB. Compact output still has a
  2 MiB retry limit. Retries grow only the exhausted buffer; values beyond
  these resource limits fall back.
  Stream draining protects caller-owned uploads on exceptions and cancellation.
- Shared immutable lists retain their sharing through encoding and compact GPU
  results. Deep or oversized values request source execution rather than changing
  collection semantics to fit fixed storage.
- CPU shared-prefix reuse requires an identical native starting snapshot and
  exact equality of consumed input events. Its LRU cache is limited to 64 entries
  per host. Deferred histories replay from native states, not public-state guesses.
- Source execution records reusable native CPU and CUDA checkpoints every 32
  ticks, without advancing any extra physics. CPU checkpoints are grouped by
  128-tick origins and may satisfy part of a requested advance. CUDA
  reuse compares every consumed event and the complete native origin identity.
  Both caches are bounded at 64 entries. Snapshot capture is reused only while
  the underlying sandbox remains unchanged.
- Uniform-result proofs use the same VM with conservative integer intervals.
  Unknown control flow, possible errors, physics effects, and a bounded proof
  budget reject the optimization. No named search pattern is consulted.

`forevertas-visual-runtime` tests source/compiled values, seeded random behavior,
worker lifetime, failures, fallback, shared lists, uniform proofs and cancellation.
`forevertas-block-program-physics` compares real reference/CPU/CUDA state fields,
returned snapshots, subsequent restore and continuation, histories and in-flight
cancellation. It requires the configured replay and installed packs.

## Comparable benchmarks

Export the `v0.2.3` tag to a separate directory and configure the existing build
with `FOREVERTAS_BENCHMARK_BASELINE_SOURCE_DIR` pointing there. Build
`forevertas-native-baseline-benchmark` and `forevertas-block-program-benchmark`.
The tagged search implementation and current block implementation intentionally
link the same cached ForeverValidator physics build to isolate search overhead.
This is not a comparison against the originally packaged v0.2.3 binary.

Run `python3 tests/block_program_benchmark.py --help` for fixture paths and knobs.
The driver generates an editable graph through the actual workbench builder,
alternates native/block runs, preserves raw JSON and executable/replay hashes,
checks candidate counts and block result parity across backends, rejects
unreported fallback, and reports median post-load search and end-to-end times.
The `baseline-inputs-to-completion-v1` timing contract starts both implementations
at `ApplyingBaselineInputs`, before baseline evaluation and all candidate work.
It includes subsequent search preparation. The older `Mutations` progress event
is not a valid start: native CPU emits it after the first aggregated worker update.
`--verify-interpreter` additionally checks block results against source execution.
Native and block random scheduling differ; native/block result identity is not
claimed. Automatic promotion is disabled for a comparable fixed search origin.

The default 1100 ms fixture has no eligible input edits and primarily measures
control overhead. The 6000 ms fixture performs real branch physics. Keep these
results separate. Record competing GPU/CPU workloads and use repeated paired
runs before claiming a speedup. Performance parity is not established merely by
successful compilation, a CUDA execution label, or fast no-op candidate counts.

## Earlier generic-program measurements (2026-09-06)

**The arbitrary-program throughput objective is not achieved.** In particular,
every-tick observation is substantially slower than the native comparison,
despite the final-tick-only improvements reported above. Do not extrapolate
those improvements to feedback-heavy programs.

The bytecode compiler now handles tick, checkpoint, finish, conditional and
message events, dynamic function application, and source-ordered event scopes.
Per-procedure compact local slots avoid allocating every program symbol in
every call frame. Event states retain exact capture-time semantics through
lazy state tokens; escaping tokens are materialized before simulation changes.
Publication also drains pending simulation even when its score is constant.

Unsupported instructions trap when executed rather than rejecting the entire
graph. A failed CUDA lane replays through the source interpreter with its
original arguments and seed, while completed lanes retain their results.
The execution-mode notification reports the fallback lane count. This is not
full device coverage: nested maps, in-branch native restore/restart/history and
other unsupported operations can still require source replay. Source execution
also remains authoritative for exact runtime errors and caught exceptions.

the same resumable VM and physics kernels (CUDA runtime 12.4 or newer).
It avoids host scheduling round trips at each observation. It is experimental,
not the default. A resident combined-kernel experiment was removed because
measurements did not improve throughput.

## Current generic execution

Conditional graphs are now the default on CUDA runtime 12.4 and newer.
`FOREVERTAS_CUDA_VM_GRAPH=0` selects the host scheduler; unsupported graph or
driver APIs also select it. `FOREVERTAS_CUDA_VM_SCHEDULED=1` disables its
first-wave combined-kernel heuristic. `FOREVERTAS_CUDA_VM_MONOLITHIC=1` is a
diagnostic override, except where exact host mathematics requires suspension.
`FOREVERTAS_CUDA_VM_MAX_LANES=2` forces multiple small physical waves without
changing the source-visible logical batch size.

Snapshot capture now shares immutable native extension data. Each version
stores its exact physical base and the modified collision-overflow prefix;
decoding overlays these on the shared full version. Reset, respawn, prefix
reuse and stunt mutations invalidate the shared extension. Retained versions
remain independent of later stepping and input edits. Tests restore imported
versions on the host and compare every public property after continuation.
In-branch device restore/restart/history and nested maps still require source
replay; importing a returned snapshot does not establish device support for
those operations.

The strict scalar-math test exposed a one-ULP libdevice/libm difference.
Sine, cosine, quaternion construction and rotation distance therefore suspend
their CUDA lanes for a batched host computation using the CPU VM's existing
formulas and math library. The VM then resumes with untouched operand ownership,
instruction accounting and RNG state. Other lanes can continue device physics.
An exact, per-lane last-operation cache compares operand bits, including signed
zeros, before reusing a host reply. `CUDA_VM_MATH_PROFILE` reports host waves
and operations when profiling is enabled. Scalar `min`, `max` and `clamp` also
preserve the source operand on equality rather than changing a zero's sign.
This is hybrid numeric execution, not a fully device-only math implementation.
Math-heavy loops can incur repeated host round trips, and no throughput claim
is made for them. Source math and bitwise assertions have not been relaxed.

The diversity driver now includes seven equivalent structures: direct
workbench, indirect calls, broadcasts, tick events, chunked loops, checkpoint
events and conditional events. Native CUDA batch size and Blocks CPU worker
count are separate controls; `--cuda-batch 1024` no longer incorrectly requests
1024 Blocks CPU workers. `--block-batch` still controls logical Blocks batching.
Benchmark mode transitions record seconds from the common post-load boundary,
so pre-map source work is not hidden by GPU-only timing.

The native-style comparator shares the candidate count, horizon and mutation
window, but does not assert identical candidate streams. Its winning input hash
and score differ from the Blocks oracle. These are workload-style comparisons,
not timings of a verified identical candidate corpus; source/CUDA parity is
verified separately against the Blocks interpreter.

### Experimental Source Physics Cursor

`FOREVERTAS_CUDA_SOURCE_CURSOR=1` enables a resident CUDA physics cursor under
ordinary source block control. It predicts only physics, in windows growing
from one to at most 32 ticks. Source instructions and event handlers still
execute at every consumed tick. Input edits, restores, horizon changes and
mapped execution discard the unused prediction suffix. Captures and early
stops import the last consumed state, never the device's predicted future.
Prediction failures are exposed only when the source requests the failing
tick; an already computed valid prefix remains usable.

Native extension generations are transferred only when they change. Each
predicted frame overlays its exact physics and collision delta on that
generation. The host retains independent packed frames and imports native
sandbox snapshots lazily. Cursor invalidation retains CUDA allocation buffers
so frequent controller edits do not repeatedly allocate device resources.

`FOREVERTAS_CUDA_SOURCE_LOOKAHEAD=1` disables lookahead for paired diagnostics;
positive values up to 32 cap it. With `FOREVERTAS_CUDA_VM_PROFILE=1`,
`CUDA_SOURCE_PROFILE` reports windows, predicted and consumed ticks, resets,
and transferred native bytes. This path remains opt-in until CUDA parity,
resource checks and end-to-end throughput measurements pass. The source
regression includes event-state observations, retained restores, map handoff,
frequent input edits and a count-only early stop with no publication that
could conceal an incorrect final state.

The direct-export implementation passed all seven CUDA regression suites
(`32.87` seconds total), and the source suite passed Compute Sanitizer memcheck
with zero errors. The additional source cases also passed under ASan on the
reference, optimized CPU and multithreaded CPU backends, with source and
accelerated execution enabled separately.

Initial profiling did not justify enabling the cursor. A version that built
ordinary VM snapshots and compacted them for transfer took `396.0` ms for 600
root steps, versus `321.7` ms without the cursor. Limiting that implementation
to one predicted tick still took `386.6` ms. Direct typed export, without
temporary VM snapshots or compaction, subsequently measured `292.1` and
`294.1` ms; its nearby no-cursor control measured `328.3` ms. A direct-export
one-tick control measured `286.4` ms. These are diagnostic runs, not paired
throughput acceptance results: fewer launches alone did not produce the
required improvement, and the mapped-kernel timings also varied between runs.
All these runs produced identical scores and input hashes. Logs are under
`/tmp/ft-cursor-lookahead-profile-*` and
`/tmp/ft-cursor-direct-export-profile-*`; verification logs use the
`/tmp/ft-cursor-direct-export-*` prefix.

The subsequent implementation retains authoritative sandbox input validation
and regenerates the complete control plan, including nonstandard actions such
as respawn. When all predictions have been consumed without an error, an
input update preserves the device's physical state and collision scratch;
only input storage, controls, the timeline origin and export generations are
updated. An unused prediction suffix instead requires an exact rewind to the
last consumed packed state. Failed updates cannot leave a partially updated
cursor active. The regression now checks future respawn edits, 121 ordered
publications, and that frequent valid edits do not silently disable the cursor.

transfer rather than one GPU lane. The working arena now retains only staged
values, removing the obsolete 8 MiB snapshot allocation reserve. Staging size
also accounts for the allocator's power-of-two input-list buckets rather than
depending on a fixed amount of padding for large input sequences.

### Imported Snapshot Metadata

A regression reproduced an unconditional `native snapshot argument` fallback
when a map only read snapshot metadata or returned an existing snapshot.
Arguments and globals now carry immutable state/input metadata plus a compact
opaque token. Output decoding resolves that token to the original snapshot,
preserving pointer identity, native physics, input history and horizon even
when the snapshot predates the map baseline. Ordinary CPU encoding is unchanged.
This removes the blanket fallback, not the source execution required by an
unsupported operation such as restoring a snapshot inside a mapped procedure.

The regression passes snapshots through arguments and globals, repeats an
alias, reads metadata inside the map, checks identity both inside and outside
the map, publishes older states, then restores and steps each returned snapshot.

### Direct Previous-State Reads

Reading one property of `simulation/previous-state` no longer builds a whole
state value in compiled programs. The compiler emits a direct property read,
also used by checkpoint/finish event detection. CPU execution retains the
previous-state synchronization barrier. CUDA can read common physical fields
directly from the preceding native state; other properties use the existing
public-state conversion. Retaining a whole state still uses its original value
semantics. This is a generic expression optimization, not a search recognizer.

The initial implementation combined current and previous reads behind a
runtime branch. Although checkpoint throughput improved, the tick-event map
phase regressed by about 1-2%. The final implementation restores the original
current-state hot path and keeps previous reads separate.

candidates, native batch 1024, automatic Blocks batch 1024, a 6000 ms horizon,
and scoring from time zero. The source cursor was disabled, matching the
default. Both Blocks binaries were checked against source-interpreter scores,

| Broadcasts | 0.998x | 0.803x |
| Tick events | 1.000x | 0.810x |
| Chunked loops | 1.007x | 0.836x |
| Checkpoint events | 1.073x | 0.784x |
| Conditional events | 1.000x | 0.778x |

### Output Arena Growth Without Physics Replay

Output-capacity exhaustion now retains the completed VM result in its working
arena and retries compaction into the larger output arena. It clears temporary
forwarding links before recompacting every successful lane, including lanes
whose smaller outputs already fitted. Working-arena failures still require
execution retries. Growth respects the existing half-VRAM wave budget and
2 MiB per-lane output ceiling; if the larger output would require fewer lanes,
the existing wave-reduction path remains responsible for recovery.

mixed small and large results, imported and newly captured snapshot identity,
every publication, and physics after restoring decoded snapshots against
uncompiled CPU execution. The full application rebuilt and all 11 CUDA suites

fixture also passed. Evidence: `/tmp/ft-output-budget-{build,test,profile}.log`,

### Initial Global Read Proofs

Initial-value import previously encoded globals even when every access to that
name resolved to an initialized procedure parameter, or the program only wrote
the global. Adding a 70,000-element global list named like the mapped parameter
therefore exceeded the 2 MiB staging arena and forced both CUDA and compiled
CPU execution back to the source interpreter, despite the list being unread.

The compiler now records a conservative, symbol-sized initial-global read mask.
Loads and changes require initial values unless their frame slot is a parameter,
which is initialized on entry. Conditional locals retain global fallback;
reads in any compiled callee retain the global even when a caller shadows its
name. CUDA, host bytecode and uniform proofs share this metadata. Bytecode
without it imports all globals as before. No instruction, RNG operation,
source accounting or physics implementation changes, and genuinely read large
globals retain the existing capacity policy. This first proof used a linear
scan of code, parameters and local slots, rather than code size multiplied by
argument count; the following extension adds bounded control-flow analysis.

The new `shadowed-globals` diversity fixture preserves the original workbench
source result and is now included in the default diversity set. In final
alternating native/before/after triples, 16- and 64-candidate, 2,000 ms searches
improved by `4.824x` and `16.082x` over the old fallback path. Median execution
times were `1.191 -> 0.247 s` and `4.519 -> 0.281 s`; every result matched the
uncompiled CPU oracle and every new Blocks run stayed in the CUDA program
kernel. Native/Blocks ratios were `2.517x` and `2.167x` for these two cases.
Native is still not a verified identical candidate corpus.

### Required Large Values

Skipping unreachable globals does not help when a mapped program actually
reads a large collection. Initial-value encoding now retries with fresh arenas
and codecs up to a bounded 64 MiB, rebuilding every handle and imported snapshot
token together. Cancellation is checked between attempts. Inputs beyond that
limit still use source execution; output serialization retains its 2 MiB bound.
The working arena can grow to twice the rounded import size, capped at 64 MiB,
with the existing 2 MiB minimum retry limit.

GPU initialization copies each imported arena using coalesced 4 KiB tiles rather
than one lane's serial byte loop. Graph, host-scheduled and monolithic execution
all initialize explicitly, including adaptive replay. Scheduled execution also
resets each physical state from the origin before resuming the VM. No arithmetic,
RNG or physics instruction semantics change.

Large imports have six bounded power-of-two resource classes (2 through 64 MiB),
each remembering working and output growth independently. Smaller maps retain
the existing resource cache. Without this separation, one large map made a
subsequent small 1,024-lane map retain 8 MiB per lane and split into eleven waves,
although peak actual usage was only 262,048 bytes. With separate classes the
same map used one 1,024-lane wave with a 256 KiB arena. This is a resource-layout
improvement, not evidence of an unconditional end-to-end speedup.

## Cooperative Native Snapshot Copies

Scheduled execution now copies native snapshot payloads with one cooperative
CUDA block per VM lane, before the next physics kernel. Public snapshot views
are still built immediately with the same value and identity semantics. A
bounded, single pending request retains payload handles until copying finishes;
another snapshot without a physics yield completes that pending copy first.

barrier, separates copying from reference cleanup and physics mutation.

### Generic VM Restore

Restore now has its own bytecode operation rather than requesting source
interpretation. The CPU implementation follows source restoration of native
state, inputs, horizon, previous state and history, without resetting candidates
or the selected result. Retained event contexts are materialized before restore
changes their underlying physics state.

CUDA restores both imported snapshots and snapshots created inside a mapped
program. Imported contexts are prepared on demand while the device scheduler is
paused. Preparation temporarily restores the host sandbox and restores its
exact backup afterwards. Immutable native identity, time, horizon and input
equality can reuse baseline physics resources; this is not the only supported
restore path. Other origins get their own native state, tick schedule and prefix
checkpoints. Unused imported snapshots do not trigger context capture.

Generated snapshots carry their context anchor when it differs from the map
baseline. Restoration overlays their immutable native extension, physics and
collision data, and decoding reconstructs history relative to the correct
anchor. Pending cooperative snapshot copies finish before restoration can
overwrite the live state. Host context requests share the existing host-service
transport, but Restore is not classified as a scalar host-math operation.

### Generic VM Horizon Changes

`simulation/set-horizon` now lowers to a generic VM operation on CPU and CUDA.
It validates the new endpoint, preserves previous/event states, and changes
neither existing history nor selected results. CUDA lanes share lazily prepared
physical plans while retaining independent logical horizons. Extensions preserve
the original physical anchor and verify the old plan's physical tick fields.
Geometric growth and coalesced requests avoid rebuilding a plan for every small
extension; older device buffers remain alive for lanes still using them.

Snapshots retain immutable, copy-on-write duration logs. Same-time setters
coalesce without changing retained snapshots. A setter at time T affects later
history frames, not the frame already recorded at T. Decoding and deferred
history replay preserve this distinction, including after restoration to a
different physical origin. No native state approximation or named-program
recognition is used.

### History VM Foundation

The compiler now lowers `simulation/history` to a dedicated `History`
instruction rather than `Interpret`. The CPU adapter flushes pending physical
ticks, materializes the existing immutable history, and encodes an ordinary
list of full state values. Generic list operations and state-property reads
therefore work without source interpretation on CPU. Cancellation is checked
between state encodings; arena exhaustion requests fallback rather than
returning a partial list. The uniform executor does not accept this operation.

At this checkpoint the CUDA adapter did not implement `History`. Its
unsupported-operation path still requested source fallback, so the CPU
foundation did not close the seventeenth benchmark gate. That checkpoint's
benchmark SHA-256 was
`17dcd8b5a03a3e7599b410c45ec9679e931406cf59451270721fc573a29227fa`.
The CUDA implementation below replaces this remaining unsupported operation.

CTest cases passed (443.30 seconds). CPU ASan/UBSan checks passed for the base
runtime suite, mixed-event native parity and horizon/restore native parity.

### Generic CUDA History

`History` now executes on the device as an ordinary immutable list of complete
state values. Initial history and imported prefixes that an in-device restore
can make observable are encoded once per distinct history node, participate in
shared-import packing, and retain their original historical horizons.
Metadata-only imported snapshots keep their deferred histories lazy. Each
executed physics tick records its full state before event handlers can change
the horizon. Snapshot restore selects
the saved history prefix rather than keeping discarded future frames.
Checkpoint skipping remains disabled while later history reads can observe
those frames. Arena exhaustion still retries only uncommitted work with the
same inputs and seeds, under bounded wave sizes and memory limits.

Recording is not an unconditional cost of adding a history block. A
conservative reverse control-flow analysis tracks history reads through
branches, loops and calls. The VM checks both its current continuation and
every active caller before discarding its recording reference. Indirect calls
retain the conservative path. Existing lists and snapshots keep their own
immutable references. History-size limits are checked independently of this
optimization, including after restoration to another imported context.

Snapshots need an in-device history cache only when an in-device restore path
exists. Omitting that cache otherwise avoids copying the complete history
array after every publication. Output serialization also omits this private
cache, but never removes an explicitly returned history list. Exported native
snapshots retain the existing exact deferred-history reconstruction contract;
the history reporter itself does not replay physics on the CPU. History-heavy
programs have separate learned arena capacities, and a control-flow-based
initial storage estimate avoids repeated simulation merely to grow the arena.

The expanded default benchmark gate now has twenty structures: the original
sixteen, entry history, tail history, event-driven history and history returned
through an indirect call. The source graph names are test fixtures, not runtime
dispatch conditions. Restart and nested mapping remain separate unresolved
interpreter paths; adding generic history does not establish the full goal.

### Generic Restart

The compiler now lowers `simulation/restart` to `Restart`, rather than
interpreting the rest of the mapped invocation. Mapped execution carries the
enclosing runtime's initial snapshot separately from the mapping baseline.
This distinction matters when a program maps after advancing: restart returns
to the program origin, not to the point at which mapping began. Direct
bytecode callers can supply `VisualRuntimeControl::restartOrigin`; omitting it
uses their baseline without changing existing call signatures.

Both adapters preserve the current input list and horizon, restore the origin's
native and previous state, and replace history with one current state. They do
not reset variables, random streams, candidate counts or selected results.
Restart is a state-change barrier, including for deferred event observations.
The CUDA scheduler lazily prepares the origin context at the required horizon
through the existing restore/horizon mechanism. No special source graph,
procedure name or search pattern is involved.

The private duration log also retains the history reset's initial duration.
Changing the horizon again at the same timestamp updates the live duration
without rewriting that historical frame. Generated snapshots preserve this
marker across in-device restore and compact output serialization. Deferred
host history reconstruction therefore starts from the reset prefix too;
explicit history lists still contain actual device-recorded state values.
Collection limits use the reset prefix size, not the discarded history length.

The default diversity gate adds entry restart, an indirect restart after input
mutation, restart followed by history observation, and restore followed by
history observation, bringing it to twenty-four structures. The restart tests cover
map offsets 0, 990 and 2990 ms, direct and indirect calls, lane-dependent horizon
shrinkage/extension, frozen events, 131 pending ticks, and independent source
replay after restoring each exported snapshot, both with and without a device
history reporter. Resource tests retain snapshots and lists across 8,192
double resets per lane; separate infinite loops exercise cancellation.
Nested mapping remains a separate interpreter path, so this addition is not
a claim that every programmable workload meets the full performance goal.

Snapshot history retention also uses a conservative future-restore proof.
The proof checks the current continuation and every active caller; indirect
calls retain the conservative path. A restart or horizon context does not by
itself make an earlier snapshot's private history observable. Likewise, an
entry restore need not keep caches alive through a later evaluation that can
never restore them. This removes repeated copying of the history array after
publications in those cases, while retaining the cache when a future restore
can use it. Explicit history lists and exported native snapshots keep their
existing immutable and deferred-reconstruction contracts.

Snapshots that really can be restored later still use the existing
copy-on-write history cache. This proof does not optimize that representation;
its retention costs remain a separate performance audit.

This interaction was measured before the fix, rather than omitted from the
gate. In a 64-candidate diagnostic, entry restart alone ran at 1.2905 times
native throughput, but restart plus tail history fell to 0.5659 and restore
plus tail history to 0.5540. A subsequent three-pair 64-candidate diagnostic
measured those combinations at 1.4367 and 1.4454 respectively, with source
parity. These small pilots are not the final throughput gate. Raw evidence is
retained in `build/verification/vm-dispatch/restart-history-cliff/` and
`build/verification/vm-dispatch/restart-continuation-probe/`.

### Live Snapshot History Prefixes

The twenty-fifth default fixture, `mapped-result-restore-history`, observes
history after evaluation and restores the selected result before observing it
again. Unlike the earlier unused-cache fixtures, its snapshots genuinely need

(`live-history-large-cliff/`). The corresponding 64-candidate diagnostic had

Private history descriptors now retain an immutable logical prefix length
independently of the backing allocation's physical length. Appending at the
physical end can share storage with older snapshot prefixes. Restoring an
earlier prefix and then advancing detaches that branch. Imported histories
always detach before writing. Public history reporters return ordinary,
independent lists, never the private appendable storage; generic list semantics
and public value representation are unchanged. Final release owns all physical
frames, including suffixes hidden from retained prefixes. Export continues to
omit private caches and reconstruct exact native history as before.

The mapped-history regression now advances a restored older snapshot along a
different input branch, retains both histories, restores both branches again,
and compares the full state lists and subsequent native state with source
execution. This supplements the existing imported-prefix, horizon, restart,
