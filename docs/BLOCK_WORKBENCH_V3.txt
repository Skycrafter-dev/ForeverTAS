# Blocks architecture

The embedded Blockly editor is a visual source editor, not a native search configuration editor. Its authoritative semantic graph is parsed and validated in C++ before execution. The interpreter executes that graph directly on the chosen physics backend. The native search configuration model remains a separate application path; no visual graph is lowered into it.

## Source layers

`visual_catalog.cpp` defines only language constructs and single-purpose primitives. `visual_macros.cpp` builds preset source sequences exclusively from those definitions. `BlockEditorBridge` publishes their metadata and ordinary Blockly stacks; inserting one assigns fresh IDs and variable names. Serialization, procedure reuse, validation, execution and debugging are exactly the same for an inserted sequence and a sequence the user created by hand. There are no macro opcodes or native mutation/evaluator callbacks.

`visual_compiler.cpp` validates and retains an executable `VisualProgram`. It does not recognize special search shapes or produce `SearchComponentConfiguration`. `visual_runtime.cpp` owns flow, variables, procedure calls, events, snapshots, input editing and explicit publication. The physics host supplies ticking, state capture/restore and input application. The debugger communicates through thread-safe checkpoints to the editor's source-block mapping.

## Verification

Visual language tests reject retired wrappers and check macro source structure, graph integrity, types and procedure validation. Runtime tests exercise every reporter, all expanded templates, single-input edit invariants, hold/collision behavior, selection provenance, branch isolation, debugging and cancellation. The Chromium test inserts every template through the actual editor, validates its serialized output in C++, and checks variable isolation, undo/redo and reload. Optional installed-game tests exercise real physics and the native debugger lifecycle.

See [the sandbox guide](BLOCKS_SANDBOX.txt) for user-visible semantics and [the workbench guide](BLOCK_WORKBENCH_GUIDE.txt) for authoring. Package/release verification is separate from runtime verification and must be repeated for a release.
